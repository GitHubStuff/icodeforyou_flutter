# Mason Setup in a Melos Monorepo

Principled setup for enabling Mason in a brand-new Melos-managed monorepo: no Homebrew tap (it pulls a second Dart SDK), `mason_cli` as a dev dependency of the workspace root, invoked through FVM. Everything hangs off the root `pubspec.yaml`, since Melos configuration lives there anyway.

## 1. Root `pubspec.yaml`

Workspace, Melos, and Mason all declared here:

```yaml
name: my_monorepo_workspace
publish_to: none

environment:
  sdk: ^3.10.0

workspace:
  # - packages/..., plugins/..., programs/... members get added as they're created

dev_dependencies:
  melos: ^7.1.0
  mason_cli: ^0.1.4

melos:
  # your melos config, scripts, etc.
```

## 2. Resolve

```zsh
fvm dart pub get
```

Now `fvm dart run mason_cli:mason` works from the root — no global activation, no second SDK, version pinned in the lockfile like every other tool. That's the whole "install."

## 3. Initialize Mason at the repo root

```zsh
fvm dart run mason_cli:mason init
```

This writes a starter `mason.yaml`. Or skip `init` and hand-write it, since it's trivial:

```yaml
bricks:
  black_velvet:
    path: bricks/black_velvet
```

`mason.yaml` is the single source of truth for brick registration. It is the only Mason file you edit by hand.

## 4. Fetch/resolve bricks

```zsh
fvm dart run mason_cli:mason get
```

This is the step that creates `.mason/` (including `bricks.json`) and `mason-lock.json`. You never create or edit those by hand — same contract as `pub get` producing `.dart_tool/` and `pubspec.lock`. Any time `mason.yaml` changes, re-run `mason get` to regenerate the cache.

## 5. `.gitignore`

```gitignore
.mason/
```

Commit `mason.yaml`. Commit `mason-lock.json` too — for path-based bricks it's low-value, but it's the lockfile-in-a-workspace convention and matters the moment you ever pull a hosted or git brick.

## 6. Optional: Melos scripts

Consistent with the Melos-as-task-runner approach — wrap the invocations as Melos scripts in the root `pubspec.yaml` so nobody has to remember the `mason_cli:mason` incantation:

```yaml
melos:
  scripts:
    mason:get:
      run: fvm dart run mason_cli:mason get
      description: Resolve Mason bricks declared in mason.yaml.
    mason:make:
      run: fvm dart run mason_cli:mason make
      description: Generate from a brick (pass brick name and vars after --).
```

Then `melos run mason:get` from anywhere in the repo.

## Directory shape when done

```
my_monorepo/
├── pubspec.yaml        # workspace + melos + mason_cli (committed)
├── mason.yaml          # brick registry (committed)
├── mason-lock.json     # generated by mason get (committed)
├── .mason/             # generated cache (ignored)
├── bricks/             # your brick sources (committed)
├── packages/
├── plugins/
└── programs/
```

## Ownership summary

| File / directory  | Who writes it | Committed? |
| ----------------- | ------------- | ---------- |
| `pubspec.yaml`    | You           | Yes        |
| `mason.yaml`      | You           | Yes        |
| `bricks/`         | You           | Yes        |
| `mason-lock.json` | `mason get`   | Yes        |
| `.mason/`         | `mason get`   | No         |
